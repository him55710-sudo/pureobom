- **예시 첨부 최종 검증:** `7a6e368`의 [Windows·Ubuntu CI](evidence/local-ai/explanation-observations-ci.json)는 각 핵심 312개·개발/production 설치 각 64개·설치 파일 11개 해시·패키지 검사를 통과했다. 실제 모델 품질이나 모든 언어의 계산 지원을 증명하지 않는다.

- **계산 출처 이동 후속:** [다른 파일의 정확한 원본 줄 이동](TRACE_NAVIGATION.md)을 연결하고 최신 계산 식별자·원문 일치 확인을 추가했다. 핵심 부분 108개·개발/production 설치 부분 각 3개 통과와 전체 native 실패 2회·직접 UI 연결 실패를 [분리 기록](evidence/local-ai/trace-navigation.json)한다. 프로젝트 전체 검증이나 모델 품질 근거는 아니다.
- **출처 이동 최종 검증:** 긴 경로 표시를 포함한 `13752f4`의 [Windows·Ubuntu CI](evidence/local-ai/trace-navigation-ci.json)는 각 핵심 304개·개발/production 설치 각 61개·설치 파일 11개 해시·패키지 검사를 통과했다. 위 로컬 전체 실패와 직접 UI 미확인을 해소했다고 하지 않는다.
- **실제 대상 계산 후속:** [한도 있는 while·배열 콜백](BOUNDED_PREVIEW.md)으로 앞서 확인 불가였던 원래 대상 함수를 제품 worker에서 계산했다. 프로젝트 원래 assertion 3사례와 선정 11사례가 Node와 일치했고 소스를 보존했다. 앞선 미지원 기록은 당시 버전 근거로 유지한다. 전체 언어·모든 입력·모델 설명/수정·성능 최적화의 완료가 아니다.
- **반복 계산 검증:** `5242fcc`의 [Windows·Ubuntu CI](evidence/local-ai/iteration-preview-ci.json)는 각 핵심 301개·개발/production 설치 각 58개를 통과했다. 로컬 전체 첫 timeout 및 해당 SDK 검사 재실행 17개 통과, 브라우저 연결 실패, 당시 남은 다른 파일 trace 이동 결함은 [상세 기록](BOUNDED_PREVIEW.md)에 분리했다. 이동 결함의 후속 수정은 위 별도 근거를 따른다.

- **표시 보완 검증:** 기능 커밋 `66a6781`의 [Windows·Ubuntu CI](evidence/local-ai/preview-values-ci.json)는 각 핵심 266개, 개발/production 설치 각 57개와 추출 도구 검사를 통과했다. [PR #1](https://github.com/him55710-sudo/pureobom/pull/1)의 격리 변경안이며 기본 브랜치 반영·안정 릴리스 배포와 구분한다.
- **0.7 개발 소스:** 로컬 Ollama 연결, 정확한 원문에 연결한 다중 범위 편집, native diff·적용·undo, 기존 프로젝트 명령 실행, 전후 시간·메모리 측정이 있다. 공개 안정판과 Pages 데모는 **0.6.0**이며 새 기능 배포와 구분한다.
- **설명 대상 연결:** [선택한 함수 설명](FOCUSED_EXPLANATIONS.md)을 읽기 화면에 연결했다. 호스트가 최신 원문 범위를 확인하고 해당 함수의 실제 인용을 요구한다. 전체 원문을 선택 함수와 앞뒤 문맥으로 구분해 보존한다. 첫 두 실제 요청은 timeout, [후속 CPU 응답 세 건](evidence/local-ai/focused-context-cpu.md)은 인용 또는 의미 검토에 실패했다. 요청별 CPU 선택은 제공하지만 실제 과제의 설명 품질은 아직 부족하다.
- **함수 선택 후속 검증:** CPU 옵션과 원문 구분을 포함한 `954d6cf`의 [Windows·Ubuntu CI](evidence/local-ai/focused-context-cpu-ci.json)는 각 핵심 260개·개발/설치 각 55개·파일 11개 해시·추출 도구 실행을 통과했다. 로컬에서도 같은 수가 통과했으며 이전 시도의 Java timeout은 별도 실패로 남긴다. 실제 사용자 프로젝트의 모델 품질이나 원격·모든 환경 지원을 입증한 결과는 아니다.
- **사용자 지정 실제 프로젝트 후속:** JS/TS 원문 비교와 사용자가 선택하는 [공백·줄바꿈 제한](evidence/local-ai/whitespace-constraint.md)을 추가했다. 실제 요청 밖 변경의 호스트 적용 차단을 확인했지만, 해당 실제 유지보수 과제의 모델 수정은 아직 실패다. 비교·차단 기능을 요청 달성이나 최적화 성공으로 세지 않는다.
- **모델 없는 함수 정리:** [선택한 JS/TS 함수의 줄바꿈 정리](FUNCTION_FORMATTING.md)를 추가했다. 사용자 프로젝트의 실제 함수에서 명시적 적용·기존 테스트 **8→8→8 통과**·native undo·원본 복구를 확인했다. 이는 요청의 서식 부분을 해결한 별도 경로이며 모델의 설명·수정 품질이나 성능 최적화 성공은 아니다. [검증 기록](evidence/local-ai/function-format.md).
- **모델 없는 원문 읽기·수정:** JS/TS의 일부 구문·JSX, [JSON/JSONC](JSON_DATA.md), 설치 도구를 사용하는 [Python](PYTHON_SOURCE.md)·[Go](GO_SOURCE.md)·[Java](JAVA_SOURCE.md)·[C#](CSHARP_SOURCE.md), 포함된 파서의 [HTML/CSS](HTML_CSS_SOURCE.md)·개발 검증 중인 [Rust](RUST_SOURCE.md). 전체 구문·타입·프로젝트 의미 분석을 제공하는 것은 아니다.
- **실제 외부 검사:** Python itsdangerous, JavaScript clsx, Go Google UUID에서 고정 오류 발견과 undo 복구를 확인했다. [HTML/CSS modern-normalize](evidence/local-ai/web-source-project.md)는 Chrome 전체 54개 중 실패 **7→9→7**을 확인했다. 원래 실패와 assertion 없는 TODO 8개를 보존한다. 모든 외부 프로젝트가 전체 통과했다는 뜻은 아니다. [Java minimal-json](evidence/local-ai/java-source-project.md)은 별도 JDK 호환 adapter로 452 pass → 고정 오류 13 fail → undo 후 452 pass를 확인했다.
- **SQL 증분:** [명시적으로 선택한 SQLite 읽기·리터럴 수정](SQL_SOURCE.md)을 추가했다. [외부 sqlc 예제](evidence/local-ai/sql-source-project.md)는 공식 재생성과 원래 테스트로 1 pass → 고정 LIMIT 오류 1 fail → undo 후 1 pass를 확인했다. 다른 SQL 방언·스키마·쿼리 성능·모든 식의 자연어 설명은 미제공이다.
- **설치 후속:** Rust 초기 로컬 설치 54개 성공 이후 한도 보완본의 로컬 재검사는 Rust 이전 단계에서 실패했다. [시도별 기록](RUST_SOURCE.md)을 유지한다. 최종 제품 커밋 `7df2ee6`의 [Windows·Ubuntu CI](evidence/local-ai/rust-source-ci.json)는 각 핵심 258개, 개발/production 설치 각 54개, 실제 파일 11개 해시·추출 Rust worker 실행을 통과했다. CI 패키지의 결과이며 안정 릴리스 게시나 모든 수동 UI 검증은 아니다.
- **C# 외부 연동:** [GuardClauses](evidence/local-ai/csharp-source-project.md)에서 원래 테스트 959 pass → 검증용 경계값 편집으로 7 fail → native undo 후 959 pass와 원본 복구를 확인했다. 첫 실행의 BOM 위치 처리 오류는 검증 스크립트에서 수정했고 실패 기록을 보존했다. 실제 발견한 upstream 버그나 모델 품질·최적화 사례가 아니다.
- **Rust 외부 연동:** [humantime](evidence/local-ai/rust-source-project.md)의 원래 테스트 42 pass → 고정 상수 오류 8 fail → native undo 후 42 pass와 원본 복구를 Windows에서 확인했다. 앞선 Windows·Ubuntu 제품 CI와 별도 사례다. 실제 외부 프로젝트의 Linux 실행과 다른 SDK 조합은 남아 있다.
- **남은 우선순위:** 사용자 지정 실제 프로젝트의 일반 모델 수정·설명 품질, 로컬 실행 지연과 검사 시간 초과의 원인 확인, Rust 외부 프로젝트 Linux 검증, C# 새 설치본 수동 UI 검증과 다른 SDK 조합, 다른 SQL 방언, 모델의 분기·경계·데이터 의미 오류, 환경별 사용 흐름, 실제 성능 개선의 근거다. 이미 측정한 Python 모델 제안은 느려져 채택하지 않았다. 원격 VS Code·모든 브라우저·모든 언어 정확성은 보장하지 않는다.

제품 소스 `0a95520`의 [Windows·Ubuntu CI](https://github.com/him55710-sudo/pureobom/actions/runs/39289761695)는 각각 핵심 **242개**, 개발/설치 각 **51개**, production 모드·패키지 파일 9개 해시와 C#을 포함한 추출 도구 실행에 성공했다. [CI 원자료](evidence/local-ai/function-format-ci.json). 실제 외부 프로젝트와 수동 화면 검사는 별도 기록이며 CI 수에 합치지 않는다. 새 C# 외부 harness의 BOM 수정은 이 CI 이후다. 좁은 화면·직접 수정 범위·별도 언어 서버의 진단 대기 등 사용성 제약은 남아 있다. 이전 커밋별 CI와 설치본·실제 모델 기록은 작업 기록에서 추적한다.

## 요청과 우선순위

비개발자가 AI로 만든 코드를 자신의 말로 이해하고, 설명에서 수정하고, 결과를 검증하며 최적화한다. 주 제품은 VS Code 확장이다. API 사용료 없이 사용할 수 있어야 하며, 여러 프로그래밍 언어와 실제 프로젝트에서 작동해야 한다. 사용자는 Ollama 로컬 모델 활용을 허용했다. 공개 기획과 에이전트의 변경·실패·검증 기록을 먼저 갖춘다. 모집·홍보·Marketplace 계정은 이 개발의 선행 조건이 아니다.

## 구현할 사용자 흐름

1. 프로젝트를 열면 지원 언어, 분석 가능한 범위, 필요한 로컬 도구를 확인한다.
2. 모델 없이 문법 기반 설명을 읽거나, 설치된 Ollama 모델을 선택한다. 최초 설치와 모델 다운로드에는 인터넷·디스크 공간이 필요하지만 로컬 추론에는 유료 API 키가 필요하지 않다. PC의 메모리·연산·전력 비용은 남는다.
3. 로컬 AI를 실행하기 전에 전달할 현재 파일, 크기, 작업 목적을 확인한다. 프로젝트 전체·비밀 설정·대화 기록을 자동 첨부하지 않는다.
4. 한국어 또는 영어로 목적·흐름·변경 지점을 읽고 코드 근거로 이동한다. 문법 분석 결과와 모델 추론을 구별한다. 모델이 인용한 원문은 실제 파일과 대조한다.
5. 자연어 수정 또는 최적화를 요청한다. 모델은 변경안을 제안하고, 프로그램이 실제 원문과 범위를 검증한다. 자동 실행·자동 적용·자동 저장은 하지 않는다.
6. 변경 전후 차이, 검증 결과와 남은 불확실성을 보고 적용하거나 버린다. 파일이 바뀌면 이전 제안은 무효이며 정상적인 편집기 undo가 가능해야 한다.
7. 최적화는 결과 동일성 검사와 측정을 함께 남긴다. 측정하지 않은 제안에 속도 향상 수치나 '최적화 완료'를 붙이지 않는다.

언어 이름을 목록에 추가하는 것만으로 지원 완료로 세지 않는다. **파일 읽기 / 문법 기반 설명 / 모델 설명 / 모델 수정 / 문법 검사 / 프로젝트 테스트 / 최적화 측정**을 따로 표시한다. 모델 설명을 받을 수 있어도 해당 언어의 분석기·테스트 도구가 구현된 것은 아니다. 언어·사례별 기록은 [지원 및 검증 표](LANGUAGE_SUPPORT.md)를 기준으로 한다.

## 연결 설계

Rust 전용 경로의 사전 [구현 계획](RUST_SOURCE_PLAN.md)에 이어 [0.7 개발판 읽기·값 수정·AI 문법 검사](RUST_SOURCE.md)를 연결했다. Windows·Ubuntu CI에서 개발/설치 각 54개와 포함된 WASM 실행을 확인했다. 별도 Windows 실제 편집기에서 [humantime의 원래 검사](evidence/local-ai/rust-source-project.md) 42 pass → 고정 시간 상수 변경으로 8 fail → undo 후 42 pass·원본 복구를 확인했다. 모델 의미 정확성·최적화·다른 SDK/환경을 포함한 전체 지원 완료로 처리하지 않는다.

- 첫 연결은 데스크톱 VS Code 확장 호스트에서 `127.0.0.1`의 Ollama HTTP API로만 한다. 외부 주소·리디렉션·클라우드 모델·유료 API로의 자동 대체를 허용하지 않는다. 원격 VS Code와 공개 웹 데모에서 로컬 PC에 연결하는 기능은 별도 검증 전까지 지원으로 표기하지 않는다.
- 모델의 JSON 출력도 검증해야 하는 입력이다. 인용은 실제 문자열, 변경은 유일한 원문 범위에 연결한다. 모델은 파일 경로, 셸 명령, 네트워크 주소, 적용 여부를 실행 권한으로 사용할 수 없다.
- 모델 선택과 요청은 사용자의 명시적 조작으로 시작한다. 큰 요청을 몰래 자르지 않는다. 코드 내용은 로그·공개 피드백에 자동 저장하지 않는다.
- 로컬 문법 분석·편집 경로는 모델 없이도 유지한다. 무거운 분석과 추론은 UI와 분리한다. 요청 중 파일 변경·탭 전환·취소를 처리한다.

## 실제 프로젝트 검증 방법

사용자 추가 요구(2026-10-20): 만든 예제·고정 오류 검사만으로 실사용 가능성을 판단하지 않는다. 사용자가 직접 지정한 자신의 프로젝트에서 기존 코드·기존 검사와 실제 유지보수 요청을 평가한다. [실제 프로젝트 평가 절차](REAL_PROJECT_EVALUATION.md)에 따라 읽기·설명 정확성·수정 의도·기존 동작·편집기 연동·사용성을 구분하고, 비공개 소스는 공개 증거 자료에 넣지 않는다. 이는 기존 P2–P6를 대체하지 않고 그 실사용 근거를 보강하는 요구다.

본 저장소만 분석한 결과를 외부 프로젝트 검증으로 부르지 않는다. 공개 라이선스를 확인한 외부 저장소를 별도 검증 폴더에 고정 커밋으로 가져온다. URL·커밋·대상 파일·작업 목적·수정 diff·검증 명령·도구 버전·결과를 공개한다. 원격 저장소에 변경을 보내지 않는다. 비공개 사용자 파일·계정·토큰은 공개 자료에 포함하지 않는다.

외부 프로젝트의 기존 테스트와 변경 후 테스트를 구분하고, 모델 추론은 모델 이름·digest·환경·시간을 남긴다. 가짜 HTTP 서버 검사와 실제 Ollama 검사를 별도 집계한다. 모델 실패·틀린 설명·수정 거절도 기록한다. 테스트 성공은 사용성·전체 언어 정확성·수요를 증명하지 않는다.

## 공개 기록 규칙

각 작업 기록에는 목적, 실제 변경 파일, 사용한 외부 자료, 실행한 검증과 결과, 발견한 실패, 남은 범위, 커밋 또는 후속 연결을 남긴다. 이전 세션의 비공개 내부 추론이나 도구 로그 전체를 지어내지 않는다. 과거 작업은 Git 이력과 남은 검증 파일로 확인 가능한 것만 소급 정리한다. 비밀·개인정보를 제외한 재현 가능한 작업 사실을 공개한다.

## 완료 판단

P0–P6의 근거가 모두 있어야 이 계획을 완료로 바꾼다. 미설치 도구나 외부 게시 권한 부족을 다른 구현 작업을 중단하는 이유로 사용하지 않는다. 제약은 구체적으로 기록하고 가능한 독립 작업을 계속한다. 모든 언어·모든 프로젝트에서 완벽하다는 보장은 하지 않는다.
